The map: modules, layers and one request

Before you can change anything, you need to know where it lives.

Time ~10 minPrereq noneDeep dive docs/02-architecture.md
Your win

Given any screen in the admin UI, you can name the Vue file that renders it and the Java controller that serves its data.

Two repos, one contract

maku-admin-frontend is a Vue 3 SPA. maku-boot-backend is a Spring Boot 4 monolith. They speak JSON over HTTP, and every response has the same envelope — the Result:

{ "code": 0, "msg": "success", "data": … }   // code ≠ 0 means failure — even though HTTP status is 200

Source: maku-framework/…/common/utils/Result.java. The frontend checks res.code, not the HTTP status (src/utils/request.ts).

Backend: six Maven modules

ModuleHoldsYou'll touch it when…
maku-frameworkInfrastructure: security filter, MyBatis base classes, Redis, Result, exceptionsrarely — it's the foundation
maku-boot-systemUsers, orgs, roles, menus, dicts, logs, storage, SMS, emailchanging core admin features
maku-boot-module/*Optional features: quartz, websocket, monitor, member, generatorworking on those features
maku-boot-apiSmall interfaces (SmsApi, StorageApi)one module needs another's service
maku-boot-newEmpty skeleton, package net.maku.moduleadding new business features
maku-serverServerApplication + application*.ymlconfig, wiring modules in

ServerApplication sits in package net.maku, so Spring's component scan picks up every net.maku.* bean from every module on the classpath. Adding a module = adding a dependency in maku-server/pom.xml.

Every feature has the same shape

Inside a module, one feature = one file per layer. The simplest complete example is Posts:

controller/SysPostController   @RequestMapping("sys/post")  → returns Result<T>
service/impl/SysPostServiceImpl extends BaseServiceImpl<SysPostDao, SysPostEntity>
dao/SysPostDao                  extends BaseDao<SysPostEntity>   (MyBatis-Plus mapper)
entity/SysPostEntity            extends BaseEntity, @TableName("sys_post")
vo/SysPostVO · query/SysPostQuery extends Query

From screen to file

The sidebar is not hard-coded. After login the UI calls GET /sys/menu/nav and turns each sys_menu row into a route. A menu whose url is sys/post/index mounts src/views/sys/post/index.vue. That page calls /sys/post/page → SysPostController.

See generateRoutes() in src/router/index.ts; it uses import.meta.glob('/src/views/**/*.vue'). Vue Router's dynamic routing guide explains addRoute.

The trick: to find any screen's code, open Menu Management, read the menu's URL, and you have the Vue file. Open the Vue file, find the URL it calls, and grep the backend for the @RequestMapping.

Practice

Answer from memory first. Wrong clicks are fine — they're how this sticks.

1. You're adding a brand-new business feature (not core system management). Which module is it meant to live in?

maku-boot-new is the empty skeleton for your code (sample TestController at /new/test). maku-framework is infrastructure with no business logic; maku-server only wires things together.

2. A sys_menu row has url = "sys/user/index". Which file renders it?

getDynamicComponent(path) looks up /src/views/${path}.vue. src/api/ holds HTTP wrappers, src/layout/ the shell.

3. A module needs a new endpoint that works without logging in. Where is that declared?

PermitResource merges auth.ignore_urls from every classpath*:auth.yml; SecurityFilterConfig then calls permitAll() on them. Each module can ship its own auth.yml (e.g. the generator's /maku-generator/**).

4. Put one authenticated request — “load the post list” — in order.

  1. FEaxios interceptor adds Authorization: <token>
  2. BEAuthenticationTokenFilter loads the user from Redis
  3. BE@PreAuthorize checks the permission code (if present)
  4. BEService + MyBatis-Plus query MySQL
  5. BEResult.ok(page) is serialized to JSON
  6. FEResponse interceptor checks code === 0
This is the spine of every later lesson: lesson 02 zooms into steps 1–2, lesson 03 into step 3, lesson 04 into step 4.
Recall: why does adding a new module only require a pom dependency, with no extra Spring config?

ServerApplication is annotated @SpringBootApplication in package net.maku; component scanning covers all sub-packages, and every module uses net.maku.*.

Try it in the real app

Run the stack (docs/06), log in as admin/admin, open System Settings → Menu Management, pick “Data dictionary”, and follow it to its Vue file and controller. Time yourself — aim for under two minutes.
