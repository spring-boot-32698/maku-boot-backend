How a Quartz job finds your code

schedule_job: bean_name = "testTask", method = "run", params = "hello", cron = "0 0 2 * * ?"
AbstractScheduleJob → SpringUtil.getBean("testTask").getClass()
                     .getDeclaredMethod("run", String.class).invoke(bean, "hello")
                     → schedule_job_log (duration, status, error)

No annotation, no registration code — the DB row is the registration, and admins can change the cron in the UI. See maku-module-quartz/…/task/TestTask.java.

Quartz concepts (jobs, triggers, cron): Quartz documentation.

Practice

Pick the idiomatic tool for each requirement.

1. The Excel export of products must show “Enabled/Disabled” instead of 1/0.

Exactly what SysUserExcelVO does: @Trans(type = TransType.DICTIONARY, key = "user_status", ref = "statusLabel"). The export is generated server-side, so a frontend component can't help. Note: JSON responses are translated automatically by TransResponseBodyAdvice, but for Excel you call transService.transBatch(list) yourself (see SysUserServiceImpl export).

2. Purge expired carts every night at 02:00; ops must be able to change the time without a deploy.

A schedule_job row is editable in Scheduled Tasks, logged in schedule_job_log, and can be paused or run on demand. @Scheduled hard-codes the cron.

3. Admins need to switch “allow self-registration” on and off at runtime.

Same pattern as LOGIN_CAPTCHA: sysParamsService.getBoolean("…"), editable under Parameter Management. YAML and env vars need a restart.

4. You added @OperateLog to save(), saved a product, and the row isn't in sys_log_operate yet. Why?

OperateLogAspect → OperateLogService.saveLog pushes onto Redis list sys:log; SysLogOperateServiceImpl drains it every 10 s, 10 entries at a time.

5. Show an in-app toast to one specific logged-in user the moment their export finishes.

WebSocketSessionManager.getSessionList(userId) gives that user's open sockets; POST /ws/message/send is the existing example.
Recall: your Quartz job calls SecurityUser.getUserId() and gets null. Why, and what follows for creator on rows it inserts?

Jobs run on a Quartz thread with no HTTP request and no SecurityContext. FieldMetaObjectHandler skips the user fields, so creator/updater/org_id stay null — and those rows are invisible to SELF-scoped users.
