Kubernetes & Helm, with maku

Learn Kubernetes by taking apart — and then rebuilding — a real deployment of this project.

Mission

Deploy and operate maku on Kubernetes with Helm, confidently enough for work and for interviews. MISSION.md

How this course works. maku is already running on your local cluster (deploy/k3d/up.sh did it). Each lesson explains one layer of that working system, then you poke it with real commands. In lesson 9 you tear it all down and rebuild it by hand. The chart you're studying: maku-boot-backend/deploy/helm/maku · guide: deploy/helm/README.md.

Part 1 — Core objects

  1. 01The cluster and desired stateWhat a cluster is, who does what, and why deleted pods come back.
  2. 02Pods, ReplicaSets, DeploymentsRun, scale, update and roll back an app; read maku-backend's Deployment.
  3. 03Services and DNSHow the backend finds MySQL by name, and how traffic finds a pod.
  4. 04ConfigMaps and SecretsFeeding Spring Boot its settings, and why a Secret isn't a safe.
  5. 05Storage and StatefulSetsWhy MySQL keeps its data when its pod dies, and Redis doesn't.

Part 2 — Running a real app

  1. 06Probes and resourcesstartup / readiness / liveness for a slow Spring Boot app; requests, limits, OOMKilled.
  2. 07IngressFrom maku.localhost:8088 through Traefik to a pod; hosts, TLS, Gateway API.
  3. 08Helm charts from the insideChart.yaml, values, templates, include/nindent; add a feature to the chart.

Part 3 — Operating it

  1. 09Rebuild maku by handDelete everything; cluster → install → images → verify, no script.
  2. 10Ship a change and roll backNew image tag, helm upgrade, a broken release, helm rollback.
  3. 11Debugging playbookEight broken labs: Pending, ImagePullBackOff, CrashLoopBackOff, OOMKilled, not Ready, and more.
  4. 12Towards production & interviewsRegistries, GitOps, secrets, security, why maku can't scale yet, an autoscaler in action.

Ground rules

Do one lesson per sitting, roughly in order; lessons 09 and 11 are the big hands-on milestones. Predict command output before opening “Expected output”. Exercises that change things use a scratch namespace play, so maku stays healthy. If you break maku anyway: deploy/k3d/up.sh puts it back.

Your teacherAsk your agent anything, any time: “why is my pod Pending?”, “quiz me on Services”, “explain this line of the chart”. Tell it when you finish a lesson so it can record your progress and write the next one at the right level.
