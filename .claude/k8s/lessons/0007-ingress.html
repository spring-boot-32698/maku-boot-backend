Ingress

One door into the cluster, and a set of rules saying which room each request goes to.

Time ~12 minPrereq Lesson 03Namespaces maku, play
Your win

You can trace http://maku.localhost:8088 hop by hop to a pod, and expose a new app on its own hostname.

The whole path

browser  http://maku.localhost:8088/
  │  *.localhost resolves to 127.0.0.1 (no /etc/hosts edits needed)
  ▼
Docker   k3d-maku-serverlb   0.0.0.0:8088 → node port 80          (deploy/k3d/cluster.yaml: ports 8088:80)
  ▼
Service  kube-system/traefik  type LoadBalancer, 80:32011          (k3s ServiceLB exposes it on the nodes)
  ▼
Pod      traefik  = the INGRESS CONTROLLER: reads Host header, matches Ingress rules
  │  rule  host maku.localhost, path /  → Service maku-frontend:http
  ▼
Service  maku/maku-frontend → EndpointSlice → Pod maku-frontend-…   (nginx serving the Vue app)

On a cloud cluster, the first hops are a cloud load balancer instead of k3d's Docker port. From the Traefik pod onward it's identical. k3s ships Traefik pre-installed: k3s networking.

  • An Ingress object is only rules (host + path → Service). Without an ingress controller running in the cluster, nothing reads them.
  • ingressClassName: traefik says which controller should implement this Ingress. A cluster can run several (kubectl get ingressclass).
  • Routing is by Host header, which is why one port (8088) serves two sites.

Why maku uses two hostnames

The UI lives at maku.localhost, the API at api.maku.localhost. The obvious alternative, one host with /api → backend, doesn't work here: maku-boot serves its routes from / (/sys/…, /actuator/…), with no prefix to route on. Two hosts need no app changes. CORS already allows any origin, and the UI image was built with VITE_API_URL=http://api.maku.localhost:8088.

What's current (2026)The Ingress API still works and isn't going away, but it's feature-frozen. The community ingress-nginx controller, long the most common choice, was retired in March 2026 (no more fixes or security patches). New platforms are moving to Gateway API (Gateway + HTTPRoute), which Traefik and most controllers support. At work, find out which your platform uses. Interviewers like this question.

Hands-on

  1. Hop 1: the Docker port k3d published.

    docker ps --filter name=k3d-maku-serverlb --format '{{.Ports}}'
    Expected output
    0.0.0.0:8088->80/tcp, [::]:8088->80/tcp, 0.0.0.0:45685->6443/tcp   ← 6443 = the API server for kubectl

  2. Hops 2–3: the controller and its class.

    kubectl -n kube-system get svc traefik
kubectl get ingressclass
    Expected output
    NAME      TYPE           CLUSTER-IP   EXTERNAL-IP             PORT(S)
traefik   LoadBalancer   10.43.25.6   172.18.0.2,172.18.0.3   80:32011/TCP,443:30955/TCP
NAME      CONTROLLER                      PARAMETERS
traefik   traefik.io/ingress-controller   <none>

  3. Hop 4: maku's rules, resolved to live endpoints.

    kubectl -n maku describe ingress maku
    Expected output (trimmed)
    Rules:
  Host                Path  Backends
  maku.localhost      /   maku-frontend:http (10.42.1.22:80)
  api.maku.localhost  /   maku-backend:http (10.42.1.20:8080)

  4. Prove routing is by Host header: same IP and port, three different answers.

    curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: maku.localhost' http://127.0.0.1:8088/
curl -s -H 'Host: api.maku.localhost' http://127.0.0.1:8088/actuator/health; echo
curl -s -H 'Host: nope.localhost' http://127.0.0.1:8088/
    Expected output
    200
{"groups":["liveness","readiness"],"status":"UP"}
404 page not found                     ← Traefik's own reply: no rule matched

  5. Expose your own app on web.localhost.

    kubectl create namespace play        # if it doesn't exist
kubectl -n play create deployment web --image=nginx:1.27-alpine
kubectl -n play expose deployment web --port=80
kubectl -n play create ingress web --class=traefik --rule="web.localhost/*=web:80"
curl -s http://web.localhost:8088/ | grep title
    Expected output
    <title>Welcome to nginx!</title>

    Now read what you made: kubectl -n play get ingress web -o yaml. It's the same shape as deploy/helm/maku/templates/ingress.yaml.

  6. Clean up. If you re-create play immediately afterwards you may hit “namespace is being terminated”; wait for it with kubectl wait --for=delete ns/play.

    kubectl delete namespace play

TLS, briefly

HTTPS is configured on the Ingress: spec.tls lists hosts and a Secret holding the certificate. In practice, cert-manager creates and renews that Secret automatically from Let's Encrypt when you add an annotation. Our chart supports it through ingress.tls and ingress.annotations (see values-production.example.yaml). The controller terminates TLS, so pods keep speaking plain HTTP.

Practice

1. You create an Ingress in a cluster with no ingress controller. What happens?

Ingress is data. A controller (Traefik here) watches Ingress objects and configures itself. No controller, no routing. That's why k3s bundling Traefik matters.

2. curl -H 'Host: nope.localhost' 127.0.0.1:8088 returns “404 page not found”. Who replied?

The app returns JSON, never that plain text. Traefik also gives the same 404 when a rule matches but the Service has no ready endpoints, as you saw in lessons 03 and 06.

3. Why does maku use two hostnames instead of /api path routing on one host?

maku-boot's endpoints are /sys/…, /actuator/… at the root. Path routing would need a prefix-strip middleware or app changes; two hosts need neither.

4. What does ingressClassName: traefik do?

Clusters can run several controllers (say, internal and public). The class binds each Ingress to one. kubectl get ingressclass lists them.

5. Which API is the Kubernetes project's successor to Ingress?

Gateway API splits concerns (infrastructure owns Gateway, app teams own HTTPRoute) and covers more protocols. IngressRoute is Traefik's own CRD, not a standard.
Recall (interview): “A user types our URL. Walk me through how the request reaches a pod.”

DNS → external load balancer (cloud LB / k3d serverlb) → node port of the ingress controller's LoadBalancer Service → ingress controller pod (Traefik) → matches Host/path against Ingress rules → target Service → kube-proxy/EndpointSlice picks a ready pod IP → container port. Bonus points: TLS terminates at the controller; readiness decides which pods are eligible.
