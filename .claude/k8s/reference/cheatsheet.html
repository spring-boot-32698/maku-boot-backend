kubectl · helm · k3d cheat sheet

Tuned to the maku setup. Namespace maku, release maku, cluster k3d-maku.

Orient yourself

kubectl config current-context            # which cluster am I talking to?
kubectl config use-context k3d-maku
kubectl get nodes -o wide
kubectl get ns
kubectl get all -n maku                    # deploy, rs, sts, pods, svc
kubectl api-resources | less               # every object kind + short names (po, svc, deploy, sts, cm, pvc, ing)
kubectl explain deployment.spec.strategy   # built-in field docs

Look & debug

kubectl -n maku get pods -o wide -w                      # watch, with node + IP
kubectl -n maku describe pod <pod>                       # read Events at the bottom!
kubectl -n maku logs deploy/maku-backend -f              # follow logs
kubectl -n maku logs <pod> --previous                    # logs of the crashed container
kubectl -n maku logs <pod> -c wait-for-mysql             # an init container's logs
kubectl -n maku get events --sort-by=.lastTimestamp
kubectl -n maku exec -it deploy/maku-backend -- sh       # shell in a pod
kubectl -n maku get pod <pod> -o yaml                    # full spec + status
kubectl -n maku get endpointslices -l kubernetes.io/service-name=maku-backend
kubectl -n maku run t --rm -it --image=busybox:1.36 --restart=Never -- sh   # throwaway debug pod
kubectl top pods -n maku                                 # CPU/memory (metrics-server)

Change things (imperative — for learning)

kubectl create ns play
kubectl -n play create deployment web --image=nginx:1.27-alpine --replicas=2
kubectl -n play scale deploy/web --replicas=4
kubectl -n play set image deploy/web nginx=nginx:1.28-alpine
kubectl -n play rollout status|history|undo deploy/web
kubectl -n play rollout restart deploy/web
kubectl -n play expose deploy/web --port=80
kubectl -n maku port-forward svc/maku-backend 18080:8080
kubectl -n play autoscale deploy/web --cpu-percent=50 --min=1 --max=5   # HPA (needs CPU requests)
kubectl -n play create ingress web --class=traefik --rule="web.localhost/*=web:80"
kubectl -n play apply -f .claude/k8s/labs/              # the 8 broken debugging labs
kubectl delete ns play                                   # deletes everything inside
kubectl wait --for=delete ns/play                        # before re-creating it

Declarative (what real teams do): keep YAML in git, kubectl apply -f file.yaml, or let Helm render and apply it.

Helm

helm lint deploy/helm/maku -f deploy/helm/maku/values-k3d.yaml
helm template maku deploy/helm/maku -f deploy/helm/maku/values-k3d.yaml      # render locally, apply nothing
helm upgrade --install maku deploy/helm/maku -n maku --create-namespace \
     -f deploy/helm/maku/values-k3d.yaml [--set backend.image.tag=5.0.1] --wait
helm list -n maku
helm status maku -n maku
helm history maku -n maku
helm rollback maku <revision> -n maku
helm get values maku -n maku          # what you supplied
helm get manifest maku -n maku        # what was applied
helm test maku -n maku
helm upgrade … --rollback-on-failure --timeout 5m   # Helm 4 (Helm 3: --atomic); --force → --force-replace
helm uninstall maku -n maku           # PVCs from StatefulSets / keep-policy survive
helm template … | kubectl apply --dry-run=server -f -   # let the API server validate rendered YAML

Value precedence: values.yaml < -f a.yaml < -f b.yaml < --set.

k3d

k3d cluster create --config deploy/k3d/cluster.yaml
k3d cluster list | stop maku | start maku | delete maku
k3d image import maku-boot:5.0.1 -c maku               # local image → every node
docker ps --filter name=k3d-maku                        # nodes are containers
