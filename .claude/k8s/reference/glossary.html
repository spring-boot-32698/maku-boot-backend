Kubernetes & Helm glossary

One definition per term, used consistently in every lesson. “In maku” points at the real object in our chart.

Cluster

Cluster
A set of machines (nodes) run as one system, managed through a single API. In maku: k3d cluster “maku”, context k3d-maku
Control plane
The brain: kube-apiserver (the only front door, every command goes through it), etcd (key-value store holding all objects), kube-scheduler (picks a node for each new pod), kube-controller-manager (runs controllers). docs
Node
A worker machine. Runs kubelet (starts and monitors the node's pods), a container runtime (containerd), and kube-proxy (Service networking). In maku: k3d-maku-server-0, k3d-maku-agent-0 — each is a Docker container running k3s
Desired state / reconciliation
You declare what should exist (spec); controllers keep comparing it with reality (status) and act to close the gap, forever.
Namespace
A named folder for objects; names are unique per namespace. In maku: maku (the app), play (exercises), kube-system (cluster add-ons)
Context (kubeconfig)
Which cluster + user + default namespace kubectl targets. kubectl config current-context.

Workloads

Pod
Smallest deployable unit: one or more containers sharing an IP address and volumes, scheduled together on one node. Disposable — replaced, never repaired.
ReplicaSet
Keeps N identical pods running (matched by label selector). Created and managed by a Deployment; you rarely touch it. maku-backend-779d8657fd (hash of the pod template)
Deployment
Declares a stateless app: pod template + replicas + update strategy (RollingUpdate or Recreate). Each template change creates a new ReplicaSet → rollout, history, undo. maku-backend, maku-frontend, maku-redis
StatefulSet
Like a Deployment, but pods get stable names (-0, -1), ordered start/stop, and their own PVC each via volumeClaimTemplates. For databases. maku-mysql → pod maku-mysql-0, PVC data-maku-mysql-0
Init container
Runs to completion before the app containers start. wait-for-mysql in the backend pod
Labels / selector
Key-value tags on objects; selectors find objects by label. This is how Deployments find their pods and Services find their endpoints. app.kubernetes.io/component=backend

Networking

Service
Stable virtual IP + DNS name in front of a changing set of pods (chosen by selector). ClusterIP (default, in-cluster only), NodePort, LoadBalancer, headless (clusterIP: None, DNS returns pod IPs). maku-backend, maku-frontend, maku-mysql, maku-mysql-headless, maku-redis
EndpointSlice
The live list of pod IPs behind a Service, each marked ready true/false; only ready ones get traffic. Empty = selector matches no pods; all ready=false = readiness failing.
Cluster DNS
CoreDNS answers <service>.<namespace>.svc.cluster.local; within the same namespace the short name works. jdbc:mysql://maku-mysql:3306
port / targetPort / containerPort
Service listens on port, forwards to the pod's targetPort (a number or a named containerPort).
Ingress / Ingress controller
HTTP routing rules (host/path → Service). Needs a controller to implement them (Traefik on k3s). The API is feature-frozen; its successor is Gateway API, and the community ingress-nginx controller was retired in March 2026. maku.localhost → frontend, api.maku.localhost → backend
port-forward
kubectl port-forward tunnels a local port to a pod/Service through the API server — debugging only.

Configuration & storage

ConfigMap
Non-secret key-values, injected as env vars or files. maku-backend (DB URL, Redis host, profile)
Secret
Like a ConfigMap for sensitive data; stored base64-encoded, not encrypted by default — protection comes from RBAC and etcd encryption settings. maku-db (mysql-password, mysql-root-password)
PersistentVolume (PV) / PersistentVolumeClaim (PVC)
PVC = a pod's request for storage (“5Gi, RWO”); PV = the actual piece of storage bound to it. Outlives pods. data-maku-mysql-0, maku-uploads
StorageClass
How PVs are created on demand (dynamic provisioning), plus reclaim policy and binding mode. local-path (k3s default): node-local directory, RWO, reclaim Delete
Access modes
RWO ReadWriteOnce (one node), RWX ReadWriteMany (many nodes), ROX ReadOnlyMany, RWOP one pod.

Health & resources

Probes
startup: is it done booting? (others wait for it) · readiness: should it get traffic? (fail → removed from endpoints) · liveness: is it stuck? (fail → container restarted). /actuator/health/liveness, /readiness
Requests / limits
Request = what the scheduler reserves; limit = hard ceiling (memory over limit → OOMKilled).
Common pod statuses
Pending (not scheduled / waiting for volume) · ContainerCreating · Running · CrashLoopBackOff (keeps exiting) · ImagePullBackOff (can't get image) · Completed.

Helm

Chart
A package of templated manifests + default values. deploy/helm/maku
Values
Inputs to the templates: values.yaml defaults, overridden by -f file then --set (last wins).
Release / revision
One installed instance of a chart (name + namespace). Every install/upgrade/rollback creates a numbered revision. release “maku” in namespace maku
Named template / _helpers.tpl
Reusable snippets defined with define and used with include. maku.fullname, maku.labels, maku.selectorLabels
Hook / helm test
Resources run at lifecycle points via the helm.sh/hook annotation; test hooks run with helm test. templates/tests/test-backend.yaml
