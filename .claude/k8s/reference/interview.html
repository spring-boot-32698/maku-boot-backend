Fundamentals

What happens when you run kubectl apply -f deployment.yaml?

kubectl → API server (authn, authz, admission, validation) → stored in etcd → Deployment controller creates/updates a ReplicaSet → ReplicaSet controller creates Pods → scheduler binds each pod to a node (filtering on requests, affinity, taints) → that node's kubelet pulls the image via containerd, starts containers, runs probes, reports status. Lesson 01.

What's the difference between a Pod, a ReplicaSet and a Deployment?

Pod: one or more containers sharing network and volumes, disposable. ReplicaSet: keeps N pods matching a selector. Deployment: manages ReplicaSets to give rolling updates, history and rollback. You create Deployments; the rest is created for you. Lesson 02.

Deployment vs StatefulSet?

Deployment: interchangeable replicas, random names, shared template (maku-backend, frontend). StatefulSet: stable names (-0), per-replica PVCs via volumeClaimTemplates, ordered rollout, stable DNS via a headless Service (maku-mysql). Neither gives database replication; that's the database's job. Lesson 05.

What is a namespace, and what isn't it?

A scope for names, RBAC, quotas and policies. It is not a network or security boundary by itself: pods can reach other namespaces' Services (maku-mysql.maku) unless NetworkPolicies say otherwise. Nodes and PVs are cluster-wide.

Networking

Explain ClusterIP, NodePort, LoadBalancer and headless Services.

ClusterIP: internal virtual IP + DNS (all of maku's). NodePort: a port on every node. LoadBalancer: an external LB from the provider (Traefik's Service on k3s). Headless (clusterIP: None): DNS returns pod IPs, used by StatefulSets. Lesson 03.

How does one pod find another?

Through a Service name resolved by CoreDNS: <svc>.<ns>.svc.cluster.local, short name within the namespace thanks to the resolv.conf search list. The Service routes to ready endpoints (EndpointSlices) via kube-proxy. maku-backend uses jdbc:mysql://maku-mysql:3306. Lesson 03.

Walk a browser request from URL to pod.

DNS → external LB → ingress controller's Service (LoadBalancer/NodePort) → controller pod (Traefik) → Ingress rule by Host/path → backend Service → a ready pod IP → containerPort. TLS terminates at the controller. Lesson 07.

Ingress vs Gateway API? What happened to ingress-nginx?

Ingress: simple host/path → Service rules, now feature-frozen. Gateway API: role-oriented (GatewayClass/Gateway for platform, HTTPRoute for apps), richer matching, more protocols, the recommended direction. The community ingress-nginx controller was retired in March 2026, so existing users must migrate to another controller or Gateway API. Lesson 07.

A Service doesn't work. How do you debug it?

get endpointslices: if empty, the selector doesn't match labels (instant “connection refused”); if present but ready=false, readiness is failing. Then check port/targetPort names, test from a debug pod (wget svc:port), check DNS, then NetworkPolicies (timeouts). Lesson 11, labs E/F.

Configuration, storage, health

ConfigMap vs Secret? Are Secrets secure?

Both inject config as env or files. Secrets are for sensitive data, get separate RBAC, and plug into secret tooling, but they're only base64-encoded by default. Security comes from RBAC, encryption at rest, and keeping them out of git (External Secrets, Sealed Secrets). Env vars only update on restart, hence the checksum annotation trick. Lesson 04.

PV vs PVC vs StorageClass; what are access modes?

PVC = request, PV = actual storage, StorageClass = how to provision it dynamically (and its reclaim policy). RWO = one node, RWX = many nodes, RWOP = one pod. maku's uploads PVC is RWO, which is why the backend uses Recreate. Lesson 05.

Readiness vs liveness vs startup probes?

Startup: “finished booting?”, and it pauses the others (5 min for maku's JVM + Liquibase). Readiness: “send traffic?”; failure removes the pod from endpoints, no restart (includes DB + Redis for maku). Liveness: “wedged?”; failure restarts it, and it should check only the process itself, never dependencies. Lesson 06.

Requests vs limits? What's OOMKilled?

Requests: reserved, used for scheduling and HPA percentages. Limits: ceilings. Memory over limit → SIGKILL, exit 137, OOMKilled. CPU over limit → throttling. For the JVM, the limit must exceed -Xmx (maku: 1024M heap, 1536Mi limit). Lesson 06.

Helm & delivery

Why Helm? Helm vs Kustomize?

Helm: templated, parameterised charts; releases with revisions (upgrade, rollback, uninstall as a unit); hooks; packaging. Kustomize: template-free overlays and patches, built into kubectl. Helm suits distributing configurable software; Kustomize suits environment overlays of your own YAML. Lesson 08.

How do you roll back a bad release?

helm rollback <release> <rev> (it creates a new revision), or kubectl rollout undo for a plain Deployment. Prevention: readiness + RollingUpdate keeps bad pods from getting traffic, --rollback-on-failure (Helm 3: --atomic), immutable tags. Lesson 10.

RollingUpdate vs Recreate: when do you choose Recreate?

RollingUpdate gives zero downtime but briefly runs old and new versions side by side. Recreate stops old pods first, causing downtime, but needs no coexistence: use it for RWO volumes (maku-backend) or versions that can't run together. Lessons 02, 10.

What's GitOps?

Desired cluster state lives in git; an in-cluster agent (Argo CD, Flux) continuously reconciles the cluster to it. Deploy = merge, rollback = revert, drift is detected automatically. Lesson 12.

Troubleshooting

A pod is CrashLoopBackOff. Debug it.

describe (Last State: exit code, OOMKilled?; Events: liveness kills?) → logs --previous → typical causes: missing config/secret, dependency down at boot, bad command, OOM, a liveness probe too eager for a slow start. Reproduce with a sleep override or kubectl debug. Lesson 11, lab C.

A pod is Pending. Why might that be?

The scheduler can't place it: requests exceed free capacity (lab A), unbound PVC or missing StorageClass (lab H), node selectors/affinity/taints, quota. describe pod → FailedScheduling event says which. Lesson 11.

ImagePullBackOff: causes?

Wrong name or tag (lab B), private registry without imagePullSecrets, image only in local Docker and not in the cluster (lesson 09), rate limits. Events show the exact pull error. Lessons 09, 11.

Design

Is this app ready to scale horizontally? (asked about maku)

Check where state lives. Sessions in Redis ✅; migrations locked by Liquibase ✅; Quartz in-memory ❌ (every replica runs jobs; needs JDBC clustering); uploads on an RWO volume ❌ (needs object storage, which maku supports via MinIO/S3-style backends). Then switch to RollingUpdate, add a PDB, then an HPA. Lesson 12.

Would you run MySQL inside Kubernetes?

It's possible (StatefulSet + PVC, ideally an operator for backups and failover), but most teams use managed databases to offload backups, upgrades and HA. Our chart supports both: mysql.enabled vs externalDatabase. For dev and test, in-cluster is convenient. Lessons 05, 12.
